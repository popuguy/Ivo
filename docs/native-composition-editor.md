# Native composition in the editor

The new composition system is connected to the actual editor as an **explicit preview capability for a text flow**. It is not the default for existing notes and does not certify the 66-capability InDesign programme. The [shared engine](indesign/shared-composition-engine.md), [ownership contract](native-composition-ownership.md) and [PDF layer](indesign/composed-pdf-layer.md) describe its separate responsibilities.

Select a linked text frame and use **Properties → Text Flow → Composer**. **Ivo Paragraph · Preview** makes a bounded, owned whole-paragraph decision over native line measurements. **Ivo Single-line · Preview** uses the native greedy line route and supports unequal column widths. **Existing layout** explicitly returns that flow to the earlier browser composer. The initial choice is preflighted against a disposable snapshot; unsupported source or font choices leave the document unchanged. Removing the native choice retains the higher canvas capability rather than rewriting the document as an older format.

## What is connected

`native-flow-layout.js` resolves effective source styles and exact font bytes, builds unscaled inset column slots and requests native composition. Native glyph paths, line baselines, caret positions and source spans drive the page fragments. The browser never rewraps a second visible copy of a native flow. CMU's four real faces and compatible immutable vault font resources are supported; a missing real companion is rejected rather than synthesized.

One retained canonical contenteditable remains the native typing/selection owner. A view-only translation aligns its native caret query with the composed caret; source nodes, font metrics and dimensions are retained. The visible glyphs, caret and cross-frame range paint consume the composition result. Object-tool double-click enters the actual native word under the pointer, and opening an empty styled paragraph restores its insertion point inside the paragraph rather than before it. Ordinary typing, a trusted cross-page drag, partial Command-I formatting, leaving/reentering the frame, serialized archive reopen, undo and redo are exercised in the actual canvas fixture. A styled-empty-paragraph test proves insertion retains 28 pt instead of reverting to its 16 pt frame default.

Composition runs through a persistent byte-only native worker. The editor keeps one active request and one replaceable latest snapshot, releases superseded queued snapshots immediately and rejects delayed results against both source/geometry and writer-lease generations. Old ink can remain briefly while fresh layout is pending, but stale caret/range geometry cannot address the newer source. Pending native geometry also prevents moving the input to a stale frame interval. Passive windows compose without generating pages; losing writing access during a request prevents its derived result from changing or saving the document. An explicit Retry action recovers unchanged source after a transient native failure without a paint-driven retry loop. Quiet startup waits for the restored native flow's first ink or recoverable error before revealing the workspace. A deliberately held native startup response verifies that readiness does not arrive early.

Automatic continuation pages are derived, saved physical layout. Stable IDs, conservative ownership and semantic history projection allow asynchronous growth/shrink without inserting an extra undo step or breaking the next text undo. Intentional page/frame changes promote owned layout to authored content. Explicit deletion keeps remaining flow source, disables automatic recreation and remains undoable. Derived delivery refreshes the selection-bound native menu token after advancing the saved revision; formatting remains usable without another click. Typography-control rejection is consumed by its own command route; it cannot fall through and write a rejected attribute onto a frame.

The frozen PDF renderer uses the same native plan and vector glyphs. It emits affine placements and intersecting polygon masks from that frozen scene; the desktop owner validates the manifest, resolves only that job's composition tokens, and merges invisible text from the same retained native lines. This preserves exact fonts and searchable/selectable text. The visible renderer's matrix supplies placement only; it does not remeasure or reshape strings. Exported native text has an independent glyph-matrix/extraction check for rotation, nonuniform text scale, masking and mixed Roman/Italic source. Masking and occlusion do not redact extractable text.

The shared Swift engine is referenced by the iOS project and exposed on a separate serial composition queue through the Capacitor plugin. Static project/reference and Swift syntax checks pass. A mobile SDK/typecheck, physical iPhone/iPad interaction and mobile PDF recovery have not been qualified; asset sync does not establish those results.

## Supported scope and remaining work

This first editor slice supports ordinary paragraph/div/inline markup, intentional empty paragraphs and breaks, explicit document/web links, size, real bold/italic faces, leading/auto-leading, metrics/no kerning, tracking, text color, highlights, underline and strikethrough. Frame columns/insets, text scaling, first-baseline policy/minimum and top/center/bottom vertical alignment share native geometry. Paragraph mode currently requires equal column widths; the single-line route supports unequal widths. Wiki-link display remains literal source in this preview; the existing layout remains available.

Unsupported authored features are rejected explicitly instead of silently losing them. Still required are general paragraph alignment/justification, indents and spacing, hyphenation/dictionaries, keeps/grids/wraps, complete OpenType/variable-font/language shaping, portable fallback capture, structured tables/lists/anchors/notes/fields, full bidi/IME/touch/accessibility contracts and the editorial/publication systems in the programme. A native glyph primitive is not evidence that these policies already work like InDesign.

The current paragraph transport is bounded to 10k UTF-16 units, 1,024 break opportunities and 100k measured alternatives. The single-line route accepts up to 100k UTF-16 units. Source/font budgets are checked synchronously before an unsupported text edit is persisted. A flow can use up to 128 native column slots and 16 exact font resources. Frozen PDF export preflights up to 256 independently composed flows, plus the existing page and byte budgets. Export beyond those budgets fails explicitly; it does not silently publish another layout.

Fresh 10k composition in the earlier controlled native pacing witness took about 313–317 ms; a cached result took about 17 ms. Those historical numbers describe whole-result composition, not current paragraph-edit latency. Camera/frame manipulation remains independent of shaping. [Incremental paragraph reflow](incremental-paragraph-reflow.md) now reuses exact-face measurements and decisions for unchanged paragraphs, including offset shifts after insertion/deletion. Each paragraph owns its final-line policy; soft breaks remain within that paragraph. Missing alternatives share bounded whole-source native batches. The final native glyph/caret/PDF result is still composed for the complete flow. **Smaller geometry payloads, incremental final layout and broader paragraph policies remain engine requirements.** Physical input-method candidate placement, complete bidi affinity, PDF reading order/tags, cross-OS determinism and physical mobile performance remain release gates. These limits are why this capability is a preview rather than a default migration.

## Regression entry points

`test:native-editor-composition` exercises the production canvas, bridge, worker, source/history and trusted input in isolated synthetic documents. It additionally holds a native response to test stale-hit/caret rejection, verifies passive and lost-lease windows, and drives a real unsupported Properties control to prove complete rollback. `test:native-composition-geometry` checks the retained input/caret query under edits and camera changes. `test:text-composition-bridge` tests both sandboxed preloads and requester-owned tokens. `test:pdf` retains the earlier publication cases and adds the actual native rotated/scaled/masked flow.

All automated fixtures use temporary profiles and synthetic sources. Personal vaults, global permission settings and proprietary reference artifacts are not part of the tests or the public source checkpoint.
