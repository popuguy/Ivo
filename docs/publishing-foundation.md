# Publishing and text foundation

18 November 2026. This implements the first dependency-ordered portion of Paul's expanded text/layout scope. **It is not full InDesign parity.** The private reference investigation and supplied scope export remain local. This document describes Ivo's implementation, not recovered Adobe code.

## Working increment

- Independent area frames now have in/out ports alongside the eight small resize handles. Linked ports navigate their frame chain; an unlinked out port enters threading. The existing Illustrator-style point/area conversion circle and direct, smooth frame movement remain.
- A retained contextual text bar supplies font, size, fill, emphasis, alignment, OpenType and highlighting controls. Its grip moves the bar without modifying authored content. Hide it with its X; Window → Contextual Text Bar restores it. No Generate Text, AI Fit Text, Adobe Fonts service or other AI action is included.
- Properties has compact Transform, Text Style, Appearance, Character, Paragraph, Highlight, Text Frame and arrangement controls. Paragraph/character style selectors share a segmented switcher. Nine transform reference positions affect numeric X/Y and size edits. Colors, frame strokes/corners and opacity are authored. Align/arrange commands retain the existing axis-aligned geometry model.
- Named paragraph and character styles are sparse, support based-on inheritance, reject cycles, and retain direct-override ownership. Source run/paragraph references are distinct from generated CSS. Clear overrides affects selected text/paragraphs; a frame selection clears that source as a whole. This is an initial style editor, not the complete vendor style dialog.
- Character controls include Auto/fixed leading, auto-leading percentage, tracking, metrics/no kerning, baseline shift, underline/strikethrough, color and font-dependent OpenType substitutions. Imported variable fonts expose their declared axes. Paragraph controls include alignment/last-line justification, indents, space before/after, language/hyphenation, keep/widow/orphan controls and direction. Browser typography/composition supplies the current layout; it is not Adobe's paragraph composer.
- Highlighting is an authored character run with yellow, green, blue, pink, orange and purple defaults, plus custom color and removal. A replacement/removal resolves older ancestor paint rather than leaving a hidden old highlight behind it. Highlight and formatting share the document undo timeline and the frozen PDF renderer.
- Text frame columns, gutter and insets participate in linked layout. Each physical frame projects into temporary column slots; source positions are retained across those slots. Automatic continuation copies frame settings. Excessive insets/gutters are rejected. Measured first-baseline policies and Top/Center/Bottom alignment now share derived geometry across page/live/PDF output; see [frame composition](frame-composition.md). Baseline grids and full vertical justification remain open.
- Layers support naming/color, paint order, visibility, locking, object rows, moving the selection to a layer, drag reordering and non-destructive removal into another layer. Hidden artwork is excluded from paint/export; locked artwork still prints and is excluded from editing/marquee selection. Permanent groups, every nested layer gesture and full vendor layer-panel parity remain open.
- Pages lists reusable parent definitions separately, beginning with A-Parent, and page thumbnails with their parent prefix. Create a parent from an unthreaded page, apply/remove it, edit its shared definition, override its art on a page, or restore shared parent art. Parent editing uses an isolated canvas with local undo; Done or a workspace flush commits one document command. Definitions are not copied into each page until an explicit override. Parent-on-parent inheritance, facing spreads and primary threaded parent frames remain open.
- Context panels close, reopen, detach, dock, regroup and reorder. Dragging a tab shows a retained preview immediately after the movement threshold; no long-press timer is imposed. Whole groups have a close button. Closing/rearranging panels is view state and never dirties authored source. External panel windows and complete vendor docking/motion equivalence remain open.
- The selected workspace tab has no bottom outline/underline; its top/side outline and lower reverse curves remain separate from the document canvas.

## On-page text and control corrections

The bottom continuous-text pane has been removed. One retained canonical input now sits on the active page/column, shares the paint camera, clips at the frame edge and follows continuation without replacing its root. Page growth/shrinkage, source positions, selected-run formatting, IME completion, shared undo and split-pane refresh retain their owners. Copy/cut includes selected source outside the visible frame and strips projection markers. Cross-frame ranges stay anchored in their first physical column so reflow cannot hide a selected prefix and collapse the range. See [text flow](text-flow.md) for current boundaries.

Properties and contextual controls resolve actual source-owned paragraph/character formatting. Frame selection no longer displays a default font over differently formatted runs; mixed formatting has an explicit Mixed/indeterminate state. Changing a whole frame's font or size formats its source rather than leaving overriding runs untouched. Feature controls preserve the selected word when clicked.

OpenType options are anchored to the invoking control, fit above/below near canvas edges, and use one-column checkbox/real-font-preview rows. Checked, mixed and hover states update from the same text-selection summary as Properties. The shipped CMU face metadata is verified against its actual font tables; known unsupported features are hidden. Imported fonts use their declared features/axes; uninspected system fonts remain an explicit applicability boundary. The in-frame badge is for unthreaded area text; linked text keeps options in its contextual bar. Interface colors use Ivo's shared workspace palette and interface type uses Geist; font previews intentionally use the document face. Exact live native popup ordering, every feature and every native placement rule remain comparison work.

## Font portability

CMU Serif is the default for new text; the interface stays in Geist. The font picker merges the shipped faces, fonts already contained in the vault and all currently available system faces from Core Text. Refresh installed fonts updates the list without changing the document. The desktop read-only helper runs outside the renderer; the same Core Text source is included by the iPhone/iPad plugin. No global font installation, web font permission or online font service is used.

Selecting an external face validates/decodes its font data, saves an immutable content-addressed vault asset, then applies its digest to the captured text/object selection. Repeated use reuses the stored copy. Font choice shares one undo transaction; a failed save or a changed selection leaves authored text untouched. Bold/italic requests include a real installed companion where available. Medium/Semibold and other selected faces keep their exact font data rather than being rematched as Regular/Bold. Imported variable fonts retain nondefault instance coordinates and their declared axes; default optical-size/weight coordinates do not pin automatic behavior.

Existing Georgia/Helvetica presets can obtain their portable family resources without rewriting old text or typography. Vault font registration satisfies those existing names, and archive/PDF snapshots include the matching faces. Export with font resources uses archive 6, including older document sources. Manually imported `.ttf`/`.otf` faces remain supported. Installed collection/resource faces are reconstructed as portable single-face SFNTs with preserved tables and valid checksums. Original single-face files retain their bytes.

Embedding restrictions and the existing 30 MB per-asset / 100 MB archive resource budgets still apply. Unsupported/protected or oversized faces are reported rather than silently substituted. Direct `.ttc`/`.otc` file imports, compressed web fonts, complete glyph-fallback capture and physical iPhone/iPad font/input tests remain open. No font license is inferred beyond the existing metadata gate. See [font portability](font-portability.md).

The shared vault's immutable asset files already preserve images without recompression. Fonts use the same content-addressed byte IO boundary on Mac/iOS and the same asset store in IndexedDB. No Google Drive account or synchronization protocol is introduced by storing a portable font.

## Source owners and format

`domain/documents/publishing.js` owns layer/parent/style commands. `domain/text/typography.js` owns typed text attributes. `schema.js` validates archive 6 / canvas 5 publishing data; archive 5 / canvas 4 remains readable without rewriting its original bytes. A document opts into publishing capabilities on an authored mutation. Native manifest 1 and IndexedDB 4 are unchanged.

`rendering/text/styles.js`, `overrides.js`, `fonts.js` and `flow-layout.js` resolve disposable display/layout state. `features/editor/ui/` owns Properties, contextual controls, retained panels and isolated parent editing. `styles/index.css` now declares stylesheet order explicitly: existing canvas/workspace rules, then compact publishing controls. No input DOM is reconstructed solely for a camera move.

Public builds use the existing licensed Obsidian/Lucide artwork mechanism, with unchanged registry geometry for the newly needed controls. The locally available Illustrator artwork still takes precedence where mapped. Extracted proprietary artwork/code/fonts and personal font files are not committed. Exact InDesign artwork coverage, all spacing/menus, native control feel and complete visual equivalence remain acceptance work.

## Remaining scope, in dependency order

1. **Composition authority:** semantic runs/paragraph-mark ownership beyond the retained canonical HTML model; complete source/glyph/visual-order maps, baseline grids, vertical justification and incremental/stale-layout protection. [Linked selection and native command ownership](text-interaction-core.md), measured caret lines and first-baseline policies now have a tested foundation. Complete keyboard/IME/bidi/device behavior, whole-paragraph optimization, optical/per-pair kerning, hyphenation dictionaries/limits, word/glyph spacing tolerances and complex-script/CJK/vertical matrices require dedicated engine work and comparison fixtures. The [parity programme](indesign/text-parity-programme.md) owns acceptance for all included scope.
2. **Style/structure breadth:** complete style dialogs, nested/GREP/line styles, object styles, drop caps, paragraph rules, tabs/leaders, lists/numbering, column span/split, tables/cell flows, anchored/inline objects and contour text wrapping. Type on paths depends on the richer path/geometry work.
3. **Editorial/publication features:** find/GREP/proofing, footnotes/endnotes, conditions, notes/tracked changes, text variables, cross-references, tables of contents/indexes, books and data merge; structured interchange, scalable math and accessible/reflowable export. Word import remains deferred by the supplied decisions. AI features are excluded by the newer instruction.
4. **Parent/layout depth:** parent inheritance, spreads, primary parent text frames, auto page numbering/sections, per-item override controls, complete transforms/groups, complete Pages/Layers interactions and panel docking feel.
5. **Portability and scale:** direct collection-file/web-font import, font resource budgets/preflight, cloud saving/conflict handling including Google Drive, physical iPhone/iPad input/layout and large-vault performance. Existing graph/scans/OCR/region links remain in the main backlog.

These are requested work, not declarations of working buttons. No interface control is added for an absent proprietary paragraph composer, editorial feature or cloud service.
