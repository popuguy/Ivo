# Option-drag duplication

Implemented 15 November 2026. Selection and whole-object Direct Selection can move a copy by holding Option/Alt while dragging. A click or movement below the existing three-CSS-pixel threshold makes no copy. Originals stay in place; the completed copy and its placement form one document undo action. Redo restores the same new identities.

Option is live throughout the gesture. It can be pressed after movement starts, released to return to moving the original, and pressed again. Changing the modifier updates the stationary preview too. Mouse-up uses its final modifier state; releasing Option after mouse-up leaves the completed copy intact. Escape, pointer cancellation, a second touch beginning a pinch, navigation suspension and window focus loss roll back the unfinished document transaction, including copied text flows. A later hover after a consumed mouse-up cannot continue a transform.

Shift constrains moves and copies to horizontal, vertical or 45-degree directions. Shift-click still toggles selection; an actual Shift-drag moves the selection. Snapping remains active during Option-copy; Option no longer bypasses snapping for moves. Use the Snap toggle for free positioning. Centered Option-resizing is unchanged. Constrained snapping solves along the held direction and reports only guides that intersect the resulting geometry.

`src/domain/documents/scene.js` copies the selected roots and clipping descendants in one identity pass. Source order, parent-local fractional geometry, styles, crop settings, immutable media references and document links survive; polygon vertex identities are regenerated. Selected frames belonging to one text flow produce one independent copied text flow, preserving the complete canonical source and selected thread order. Automatic page creation is disabled on that copy; copying only some frames can leave overset text. This is an explicit source-preserving Ivo policy, not measured InDesign thread-duplication parity. Selecting both a mask and its descendant does not copy the descendant twice. Cross-page release transfers only the copies. Exceeding the existing object limit rejects the operation without moving originals.

## Reference boundary

Adobe's [duplication instructions](https://helpx.adobe.com/illustrator/desktop/manage-objects/edit-objects/duplicate-objects.html) establish Option/Alt-drag and Shift constraints. Its [movement instructions](https://helpx.adobe.com/illustrator/desktop/manage-objects/arrange-objects/move-objects.html) establish constrained directions. The [Adobe-hosted modifier discussion](https://illustrator.uservoice.com/forums/333657-illustrator-desktop-feature-requests/suggestions/44954005-don-t-stop-duplicating-when-alt-is-released-make) describes releasing Option before mouse-up reverting to a move; the administrator also describes modifiers as changeable during a drag. That is documentation/discussion evidence, not a new native event trace.

Native CUA resolved the installed Illustrator 2026 by its exact application path. An isolated, named 100×80pt rectangle fixture confirmed the Selection status instruction and ordinary dragging. The control API rejected a modifier-only key hold, so the attempted Option-drag did **not** establish native duplication/timing. Only that owned test document was discarded, and the original active document was restored. No personal document or application preference was edited. Existing REA/disassembly findings remain available; no new decompilation or whole-application analysis is claimed for this increment.

Copy feedback uses the actual installed `Cur_MoveCopy_1_1` and `Cur_DirectMoveCopy_1_1` SVGs and XML hotspots. As with the existing cursors, only root 64px dimensions become 32 logical pixels; artwork/viewBox are unchanged. Originals and hashes stay in private parent `work/cursor-reference/`, outside the public repository. There are now 22 staged Illustrator cursors. The Shift projection math, exact native snap acquisition/release/ranking, anchor-copy gestures and physical-device timing remain explicit fidelity boundaries.

These are application/runtime checks, not a physical trackpad or native Illustrator modifier trace.
