# First baselines and frame alignment

First-baseline controls now affect composition rather than supplying decorative inspector values. The source stores an optional policy and minimum distance; native font/line measurements determine a disposable baseline offset. Fixed uses the minimum as the baseline distance. Ascent, Cap Height, x Height and Leading use the greater of that minimum and the corresponding first-line metric. Frame insets and declared text scaling are separate from the baseline policy.

The policies follow Adobe's [first-baseline contract](https://helpx.adobe.com/indesign/desktop/format-and-style-text/tabs-indents-and-spacing/adjust-text-baseline.html) and [DOM enum descriptions](https://developer.adobe.com/indesign/uxp/omv/f/FirstBaseline/). Ivo's geometry fixture verifies a frame beginning at 100 points with a 10-point inset and an 18-point fixed offset has baseline 128 points. Native reference comparisons remain private. Other policies use real browser font measurements; matching every font/variable-axis/fallback case against InDesign remains required before calling glyph-metric equivalence complete.

`domain/text/frame-composition.js` owns policy and alignment arithmetic without a DOM. `rendering/text/frame-composition.js` measures a disposable camera-independent copy. It never inserts formatting wrappers or baseline markers into the retained source input. First-line d/H/x ink ascenders and actual line leading supply the metric policies; a measured zero-height inline marker locates the native baseline. Named styles resolve before measurement.

Linked columns with an authored policy compose with the corresponding capacity, then receive derived top/height offsets. Top/Center/Bottom alignment uses the same source and line spacing. The page renderer, projected live input and frozen PDF renderer consume that column geometry. Unlinked area frames use a positioned text surface without rewriting their HTML. Original baseline behavior is retained when no policy is authored. Source leading, paragraph spacing, words and frame geometry are not rewritten just to reposition text.

The feature requires archive 7 / canvas 6 only when authored; older publishing data remains archive 6 / canvas 5 and opens without an implicit upgrade. See [the data contract](data-format.md). `enableFrameComposition` is the mutation gate; ordinary publishing operations preserve an existing canvas 6 rather than downgrading it. Clipboard, parent definitions, native/browser storage and PDF snapshots retain the same validated capability.

Verification includes fixed/inset and scaled-baseline geometry, distinct native font metric policies, minimum offsets, top/center/bottom without leading changes, linked column placement, live-input/page agreement, PDF snapshot agreement, automatic continuation, source preservation and old/new format round trips. The dedicated isolated runtime is `tests/runtime/frame-composition/runner.mjs`. This is not a full paragraph composer: combined wrap/vertical Justify, CJK em-box policy, independent mixed-metric first lines in native unthreaded multicolumn frames and exhaustive font-fallback/variable-axis equivalence remain open.

## Document baseline grid

In Properties with no selection, **Baseline Grid** sets a common start relative to the page edge or the top margin of each page and an increment in points. **Show Baseline Grid** displays guides in the editor. The guides do not print. In Paragraph → More Paragraph options, **Align to Baseline Grid** applies to all lines or only the first line of each paragraph. A continuation in another column retains its original paragraph identity. The layout accounts for each frame’s actual vertical position, inset and text scale, including linked frames on different pages. Moving a frame re-evaluates its position against the common grid.

A hidden InDesign 22.0.0.104 comparison covered 108 grid-enabled layouts plus 36 unaligned controls. All 108 grid-enabled cases agreed on text on every row, frame, page and overset, with every baseline within 0.05 pt. The fixtures used manual and automatic breaks, mixed aligned and unaligned paragraphs, origins above and inside frames, three unequal columns across two pages, two leadings and two increments. Eighteen of 36 legacy unaligned controls differed on a line very close to the bottom edge, where Ivo's existing layout reserves full font descent. Native editor and PDF acceptance also inspect source ownership and selectable words.

## Custom frame grids and wrapping objects

In a native text flow, select a frame and open Properties → Text Frame → Options → Use Custom Baseline Grid. Start and Increment Every are physical points. Relative To offers Top of Page, Top Margin, Top of Frame and Top Inset. An enabled frame defaults to a zero offset at its top inset and 12 pt increments. Unchecked frames use the page grid. All Lines and First Line Only remain paragraph settings. Each frame can use its own origin and increment in the same thread. Each page has its own top margin and a new page inherits the preceding margin. [Adobe frame grid origins](https://developer.adobe.com/indesign/uxp/omv/b/BaselineFrameGridRelativeOption/)

Object wrapping in a top-aligned grid flow checks the space at the final baseline. Clearing an object may skip additional grid lines. Two text fragments on either side of one object keep a single baseline. The editor, caret geometry and searchable PDF use the same placements. Show Baseline Grid draws frame guides on the editing surface.

A separate InDesign 22.0.0.104 comparison covered 96 aligned page-grid layouts with Box, Shape, Jump Object and Next Column on rectangular obstacles. Another 72 aligned layouts used different grids in two linked frames and the page grid in a third, with or without a box. All 168 matched line text, frame/page, overset and baselines within 0.05 pt. Both native composers took part. The controls without alignment matched 24 of 84 layouts. The measured difference was at the last baseline near the bottom inset, where the existing unaligned route reserves font descent. Further qualifications follow below.

The editor fixture authors the overrides through Properties, checks positions, undoes a spacing change and reopens the archive. A separate PDFKit check finds all twelve words on the expected page at the expected horizontal and vertical position in the two-page wrapped export. Private comparison inputs and results are in the work folder for 20 November.

## Vertical alignment and margin-relative grids

Top Margin uses the current page’s top margin for both document and custom frame grids. Changing a page margin moves its guides and recomposes aligned text. The default margin is 36 pt. Relative To and the margin are available in Properties with no object selected.

Center and Bottom move grid-aligned lines in whole increments. Justify uses the last paragraph’s grid policy to determine the available height, then distributes it over the existing baselines. An intermediate line can land between grid lines. The shared editor and export composer matched all 760 private reference layouts for text, frame, overflow and baselines within 0.05 pt. The checks included hard and automatic line endings, mixed paragraph alignment, and different document and frame grids across two linked boxes, three frame heights and three paragraph spacing limits.

An ordinary final baseline fits at the bottom inset. Its descenders can extend below the frame. A separate 240-case reference tested three typefaces, four text samples and ten distances from the inset, both with and without a wrapping object. A further 342 rectangular-wrap cases established that a box overlapping the space between baselines reserves width on the following line. Repeating the earlier grid comparisons with both corrections matched all 144 document-grid layouts, all 144 wrapped document-grid layouts and all 108 mixed frame-grid layouts. A new margin-grid comparison with an overlapping box matched 104 of 120 layouts across Top, Center and Bottom. The 16 differences affected automatically broken paragraphs. In the six-page concave-mask study, InDesign’s Paragraph Composer leaves a row empty on page three. Switching the reference to Single-line uses that row. Grid with an overlapping object and vertical Justify, rotated page-relative grids and physical-device qualification remain open.

## Multiple openings on one line

Four controlled InDesign sweeps placed one through nine openings across a frame and varied whether short and long words could fit. Both composers could skip narrow openings before placing the first word. Once text started, each line used that opening and at most the next four geometric openings. An empty opening inside this range still consumed a place. Each new line started its own count.

Ivo applies that rule in its native and browser layout paths. Tests cover a late first word, an intervening narrow opening, repeated rows and runs with different ascents. In the six-page masked spread, the 72 pt baseline in the sixth frame is empty in both applications.

## Paragraph Composer contour edges

InDesign keeps fractional rectangle edges. For an irregular contour in an unscaled frame, its Paragraph Composer resolves line openings on a one-point grid in frame coordinates. Ivo finds the extrema where each polygon edge crosses the first and last eligible scan line. In the six-page reference, 230 occupied starts and 232 occupied ends matched exactly. The geometric paths used to edit and draw the artwork retain their precision.

At some whole-point openings, a word’s native advance exceeds the available width by a fraction of a point. In the 12 pt CMU Serif sample, InDesign resolves nominal advances at 2,048 units per em. Ivo admits such a candidate only after the native measurer checks the visible ink and the compatible advances. The placed glyphs, caret mapping and PDF use the same adjustments. Authored tracking and transformed, variable, bidirectional or compound-cluster runs keep their existing metrics. Single-line Composer keeps its continuous contour-fitting policy pending a separate qualification.

The hidden desktop editor now checks the eleven internal frame boundaries against InDesign before editing and after each of nine different insertions. Exact matches increased from 55 of 110 to 81 of 110. Total boundary displacement decreased from 4,524 to 2,155 source positions. Across those layouts, 516 rows had the same text at the same baseline, up from 322. The original spread still matches through five entire frames, with all 3,465 positions accounted for. One of the nine insertions diverges throughout. Two additional held-out passages also diverged at all eleven interior boundaries in both versions. Their total displacement increased from 1,318 to 1,500 positions.

The editor test also types, deletes, moves an image mask, and checks restoration in the twelve frames. Two fonts at a separate 13 pt setting agreed on whether 35 of 36 unfamiliar words and short phrases fit. Further work includes the tracking adjustment InDesign sometimes makes within a single word between two obstacles, combined wrap with vertical Justify, and line choices within a page.

## Paragraph breaks around partly empty contour rows

The left-aligned Paragraph Composer previously assigned a cost to partly filling an opening, yet a different word break could skip the entire opening for free. On some pages the cheaper choice left several usable baselines blank. Ivo now counts the width skipped before placing the next word. Skipping a complete open baseline also counts one column width. These distances are measured in units of the run’s ascent, independent of the authored leading. The rule applies to measured irregular contours with uniform line metrics and ordinary spacing. A fully blocked row has no available width to count. The search uses the same openings and native glyph measurements as the editor and PDF.
